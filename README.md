# PTVault

自托管的网盘迁移与媒体归档工具。按实际用途启用网盘迁移、PT 原件归档，以及 Jellyfin 媒体发布，不必为暂时不用的能力填写配置。

> **早期公开候选版本。** 当前安装目标是 Ubuntu 24.04 x86-64，运行时随发行包固定，不适用于任意 Linux/Windows/macOS。先用可保留的小样本核对自己账户的下载、恢复和播放；本地安装自检不代表你的网盘或媒体已验收。公开源码不附带账户、服务器配置、网盘文件或既有部署历史。

## 能做什么

- 在网页设置用途、文件位置、暂存预算和服务连接；已有环境配置只读展示，不被首次设置向导覆盖。
- 连接百度网盘，使用支持的 OneDrive＋crypt 账户作为加密归档目标。已有 rclone 配置可选择性导入受支持的直接组合，保留原加密参数和云端路径。
- 按分组处理目录与分卷压缩包，分别安排下载、解压和上传，避免整批输入必须同时驻盘。
- 上传后继续回读校验、保存恢复资料，再按保护条件释放临时文件。字节进度达到 100%，不代表这些步骤已经完成。
- 重试前说明预计复用哪些断点或视频结果、是否还需下载和解压。估计来自检查点，不代替执行时的文件核验。

## 数据与账户边界

1. 迁移成功不自动等于来源可删。来源清理是单独的受控能力，默认不启用；未满足校验与恢复条件不会放行。
2. PT 归档会影响做种，是否迁走由使用者判断。本项目不会把种子自动判定为“可安全迁移”。
3. 导入已有账户只复制选中的配置，不移动云端文件，不改原配置；授权仍可能受同一服务商账户的撤销或刷新规则影响，不承诺永久独立。
4. 网盘 API、配额、权限和可用性由服务商决定。连接成功不等于已完成真实文件迁移或完整灾难恢复验收。
5. 主密钥、数据库、受管 rclone 配置及恢复资料都需要保留。已有安装缺少原密钥时，不会自动生成新密钥“修复”。

## 安装与首次使用

### 1. 取得运行包并安装

支持 **Ubuntu 24.04、x86-64、systemd、Landlock ABI ≥ 4、可用的 FUSE 设备**。普通 Ubuntu 24.04 内核通常符合要求，受限制容器仍可能不允许 FUSE；安装器会检查，不会退回无沙箱解压。源码包不是运行包，不要把源码构建目录直接当成发行包安装。

从本项目发行资产取得同版本的 `linux-x64.tar.gz`、`sources.tar.gz` 和 `SHA256SUMS`。确认来源后，先校验再解包；将下面 VERSION 改为实际下载的版本：

```sh
VERSION=0.1.0-rc.5
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf "ptvault-${VERSION}-linux-x64.tar.gz"
cd "ptvault-${VERSION}-linux-x64"
sudo sh scripts/public-release/install.sh
```

安装入口自动核对文件、创建独立服务账号、初始化私密数据目录并启动服务。缺少 Python 3 或 fuse3 时，仅安装相应 Ubuntu 依赖，并禁止为此移除已有包；needrestart 仅列出建议，不自动重启其他服务。不会安装 Docker、Nginx、qBittorrent 或 Jellyfin，不修改它们的配置，不启用主机防火墙，也不替换系统 Node.js。离线准备好依赖后，可加 `--no-install-deps` 禁止安装缺失依赖。

默认端口为 **3210，仅监听 127.0.0.1**。首次安装可用 `--port 3240` 选择空闲端口；重复安装保留原端口，不会悄悄换端口。安装命令可以重复运行，已有密钥、账号、设置与任务不会重置。发现不属于本安装的同名目录/服务时会拒绝接管。

### 2. 在自己的电脑上打开网页

远程 VPS 可先建立 SSH 隧道（HOST 和登录账号按实际服务器填写）：

```sh
ssh -N -L 3210:127.0.0.1:3210 root@HOST
```

在服务器另一个终端运行：

```sh
sudo ptvault setup-link
```

在自己的浏览器打开输出的 `http://localhost:3210/setup#...` 链接。它有效期约30分钟，进入页面后会清除地址栏中的授权片段。**不要把链接、二维码或验证码贴进日志/聊天/公开问题报告。** 过期但还没创建管理员时可重新运行；管理员建立后该入口关闭，改用正常登录。若改过安装端口，隧道两端端口相应调整。

也可以接入自己维护的 HTTPS 反向代理；不要直接把 API 或 rclone RC 端口暴露到公网。安装器不改已有站点，也不代你申请域名或证书。

### 3. 按用途完成设置

首次使用流程：

1. 取得有时限的初始化链接，建立管理员密码并确认验证器。
2. 正常登录后选择用途；仅网盘迁移不要求配置 qB 或 Jellyfin。
3. 填写服务器文件位置。路径检查使用已保存草稿：先“仅保存草稿”，再检查，然后应用；也可保存并应用后检查。检查实际使用服务账号，不改权限，不把目录存在当作可写。
4. 连接百度账户，或选择性复制已有 OneDrive＋crypt 配置。rclone 源文件须能被服务账号读取；建议使用只供本次导入的副本，不要把原配置改成人人可读。只支持可核实的直接组合，不导入任意脚本、union 或间接 remote。
5. 选择两个不同的恢复账户，到恢复页保存资料并完成检查；准备好后再在网盘设置中启用新建任务。
6. 查看“已保存”和“实际生效”。应用配置等待任务和数据操作空闲，暂停并不等于排空；保留失败任务缓存时，更换数据位置仍会等待。配置失败保留最后可用配置，不倒灌旧数据库或 token。
7. 先用可保留的小样本验证迁移与恢复，需要媒体发布时另行验证 Jellyfin 的真实起播与拖动。

默认百度客户端来自清单固定的公开参考参数，授权页面显示的应用名称以百度为准；也可使用自己的应用。不承诺第三方公共客户端永久可用，不收集百度登录密码。OneDrive 新建 OAuth 应用需要相应回调设置；已有配置可选择性复制，不必为了导入重新创建应用。

## Jellyfin：挂整个导出目录，不要只挂 library

仅网盘归档可跳过此节。只看云端时，本地媒体目录可留空；安装器提供空的默认目录，不要求另建一份本地媒体。本地 PT 迁移仍须填写真实热存储位置，播放占用保护不省略。

安装器为每个目标分别管理 `blobs` 和 `ptvault-imports` 两类只读挂载，端口按持久账户槽位分配，新增账户不重排旧端口。必要时为自己的 `/srv/ptvault-public` 创建独立 shared bind，不把主机 `/` 或整个 `/srv` 改成 shared。只读 FUSE 需要 `user_allow_other` 时，会在保留原配置的前提下追加标准选项。

Jellyfin 容器需要按**同一绝对路径**只读挂入整个目录，并允许新子挂载传播。Compose 中的示例是：

```yaml
volumes:
  - /srv/ptvault-public:/srv/ptvault-public:ro,rslave
```

首次设置中的路径映射可写 `/srv/ptvault-public=/srv/ptvault-public`；在 Jellyfin 中再选择该目录下实际发布的 `library` 路径。**不要只把 library 改名挂成 /cloud**：里面的绝对链接还会指向 mounts 子目录，否则看得见条目却读不到视频。原生安装 Jellyfin 同样只需读取此独立导出目录，不应开放数据库或主密钥目录。

这一步由你按现有 Jellyfin 部署方式调整；安装器不会重建容器、删除旧库或移动原媒体。只读挂载不随 API 普通重启而停止；新增账户导致缓存份额变更、软件升级或卸载可能短暂重启受影响的挂载。

## 常用管理命令

```sh
sudo ptvault status
sudo ptvault doctor
```

`doctor` 由服务账号读取现有安装资料，核对密钥、配置、数据库和发行文件，不执行迁移、不修复或重置数据；SQLite 可能维护正常的 WAL/SHM 侧车。服务商授权、实际写权限、FUSE、恢复与播放仍需分别验证。查看服务日志可用 `sudo journalctl -u ptvault-public.service`；分享前必须脱敏。

## 开发与本地构建

需要 Node.js 24 和 npm，依赖版本以 `package-lock.json` 为准。不得把 Windows 安装出的原生 `node_modules` 复制进 Linux 发行包。

```sh
npm ci
npm run build --workspace=@ptvault/contracts
npm run build --workspace=@ptvault/api
npm run build --workspace=@ptvault/web
```

务必先构建 contracts，再构建 Web。公开源码导出包只包含经白名单选取的构建源文件和发行工具，不携带原部署测试样本或私有操作脚本，不能视为完整内部验收历史。发行工具自测：

```sh
node --test scripts/public-release/*.test.mjs
```

内部运行入口为 `apps/api/dist/cli/public.js`，包含 init/run/setup-link/doctor；普通使用者应使用上面的安装管理命令，不必直接拼接 Node 参数。源码构建不会自动下载运行时。完整的固定输入构建、源码导出和许可打包见 [发行工具说明](scripts/public-release/README.md)。公开导出会生成手动触发的 GitHub Actions 工作流，只生成构建资产，不自动创建仓库或发布 Release。

## 维护、升级与卸载

下载并校验新版本，解包后再次运行其中的安装入口，或者：

```sh
sudo ptvault upgrade --release /absolute/path/to/new-linux-release
```

升级先检查完整非终态任务和真实数据进程，关闭新的业务变更准入，优雅停服后备份控制面资料，再切换独立发行目录。**活动、排队、退避或 BLOCKED 任务存在时拒绝升级**，不会替你取消任务或丢掉断点。升级会短暂中断本安装及其只读挂载，但不重启 Jellyfin、qB、Docker 或其他 PTVault 部署。

控制面备份位于 `/var/backups/ptvault-public`，不复制大体积暂存和媒体，它们原位保留。新版本失败时只在再次确认空闲、停止完成且数据库版本兼容后恢复旧程序，不用旧数据库或旧 token 覆盖新状态；无法证明安全时停止并保留恢复材料。

```sh
sudo ptvault uninstall
```

卸载停止自己的服务/挂载并移除系统入口，**保留主密钥、数据库、账号、配置、暂存、媒体与恢复资料**。发行文件和专用服务账号也保留，方便再次运行安装入口原位恢复。不会自动执行清空数据、删除云端文件、强制卸载别人的挂载或移除共享 FUSE 设置。

主要位置：程序 `/opt/ptvault-public`；私密数据 `/var/lib/ptvault-public`；根密钥与安装管理资料 `/etc/ptvault-public`；媒体导出 `/srv/ptvault-public`。不要单独丢弃密钥，或只备份数据库而遗漏受管配置与恢复资料。
